# 服务器部署（Docker）

整套服务端跑在 Docker Compose 里，一共两个容器，另有一个可选容器：

| 容器 | 作用 |
|---|---|
| `pocketbase` | 账号、数据库、权限规则、预算提醒、鸿蒙推送。只监听服务器本机的 127.0.0.1:8090 |
| `caddy` | 对外提供 HTTPS，端口 8443；屏蔽管理后台 |
| `relay`（可选） | 公开版「两人同步」的转发服务，见下文「转发服务」。自己两个人用不需要 |

所有数据都在服务器的 `/opt/couple-ledger/data/` 目录里，迁移时整体打包带走就行。

## 用云厂商网页终端部署（不需要从 Mac SSH）

1. 在 Mac 的项目根目录打安装包。`1.2.3.4` 换成服务器公网 IP；第一次会自动签发证书、生成 `.env`：

   ```bash
   server/deploy/make-bundle.sh 1.2.3.4 1.0.0 linux/amd64
   ```

2. 用网页终端把 `dist/bundle/couple-ledger-1.0.0.tar.gz` 上传到服务器的 `/root/`。
3. 在网页终端执行：

   ```bash
   tar xzf /root/couple-ledger-1.0.0.tar.gz -C /opt && bash /opt/couple-ledger/setup.sh
   ```

   第一次会自动安装 Docker，看到「部署成功」即可。最后打印的「证书指纹」，就是 App 第一次连接时让你核对的那一串。升级时换新版本号重复这三步，数据不受影响。

## 第一次部署（从 Mac SSH）

下面的命令除第 1 步外都在 Mac 上执行，从项目根目录开始。

### 1. 服务器上安装 Docker（只做一次）

```bash
scp server/deploy/install-docker.sh root@你的服务器IP:/root/
```

```bash
ssh root@你的服务器IP "bash /root/install-docker.sh"
```

脚本最后会打印 CPU 架构：x86_64 对应 `linux/amd64`，aarch64 对应 `linux/arm64`。

另外，别忘了在云厂商控制台的安全组里放行 **TCP 8443**。

### 2. 生成证书（只做一次，换服务器时再做）

```bash
server/deploy/gen-certs.sh server/deploy/data/certs 你的服务器IP
```

- 根证书保存在 `~/.couple-ledger-ca/`。**私钥务必备份好、不要外传**。
- App 里内置的是 `ca.crt`。

### 3. 填写配置

```bash
cp server/deploy/.env.example server/deploy/.env
```

打开 `server/deploy/.env`，把 `LEDGER_HOST` 改成服务器 IP。鸿蒙推送相关的几项等华为开发者账号准备好后再填。

### 4. 构建镜像并部署

```bash
server/deploy/build-image.sh 1.0.0 linux/amd64
```

```bash
server/deploy/deploy.sh root@你的服务器IP 1.0.0 linux/amd64
```

看到「部署成功」就可以了。部署脚本同时会在服务器上添加每天 04:15 的整包备份任务。

### 5. 创建管理员账号（可选，用于在网页上查看数据）

```bash
ssh root@你的服务器IP "cd /opt/couple-ledger && docker compose exec pocketbase /app/couple-ledger superuser upsert 你的邮箱 一个强密码"
```

管理后台不对外开放，需要先建一条 SSH 隧道：

```bash
ssh -L 8090:127.0.0.1:8090 root@你的服务器IP
```

隧道保持连接时，浏览器打开 http://127.0.0.1:8090/_/ 即可。

## 升级

改完代码后，换一个新版本号，重复第 4 步即可。旧版本的镜像文件保留在 `dist/images/`，回滚时用旧版本号再部署一次。

## 备份

有两重备份：

- **PocketBase 自带备份**：每天 03:30 生成，保留 14 份，位置是 `data/pb_data/backups/`。
- **整包备份**：每天 04:15 生成，保留 14 份，位置是 `/opt/couple-ledger/backups/`。打包时会让服务暂停 1～3 秒。

建议偶尔把 `backups/` 下载到自己电脑上：

```bash
scp -r root@你的服务器IP:/opt/couple-ledger/backups ./服务器备份
```

## 转发服务（公开版「两人同步」，可选）

公开版 App 的「两人同步」不需要用户自己部署服务器：两台手机用配对码配对，数据经过这个转发服务送到对方手机。转发服务的特点：

- **看不到内容**。配对码只在两台手机上，加密密钥由它推导出来；服务器只收到房间号、密钥的哈希和密文。
- **送达即删**。每条消息给对方的每台手机各存一份，对方手机取走并确认后立即删除。没取走的最多保留 30 天。
- **不进备份**。数据在 `data/relay/`，不在 PocketBase 的备份里，每日整包备份也不包含它。
- **限额**：单次请求 512 KB，每个房间待送达 20 MB，最多 4 台手机；按 IP 限流。60 天没出现的手机、180 天没人用的房间会被自动清理。

服务器能看到的只有：手机的 IP、房间号、消息大小和收发时间。

启用方法：在 `server/deploy/.env` 里加一行（`.env.example` 里有注释好的示例），然后照常部署：

```bash
COMPOSE_PROFILES=relay
```

转发服务和 PocketBase 共用 8443 端口（Caddy 把 `/relay/` 开头的请求转给它），不需要放行新端口。

打公开版安装包（`tools/build-android.sh --public`、`tools/build-ohos.sh --public`）时，会把 `tools/relay/relay.env` 里的地址和 `tools/relay/ca.crt` 打进 App，作为默认的转发服务器。这两个文件在仓库里，所以别人从源码构建（比如鸿蒙用户）也能直接用作者的转发服务器。这个根证书只用于转发连接；构建脚本会检查，文件里要是混进了私钥就拒绝打包。

用别的服务器转发时，构建时用 `RELAY_URL=https://IP:8443` 和 `RELAY_CA_FILE=根证书路径` 指定；`RELAY_URL=`（留空）则不提供「两人同步」。

转发服务换服务器（IP 变了）时，改 `tools/relay/relay.env`（换了根证书才需要换 `tools/relay/ca.crt`），再发一个新版本的公开版 App。用户手机上的数据和配对都不受影响。

## 迁移到新服务器

1. 新服务器先执行第 1 步，安装 Docker。
2. 在 Mac 上执行迁移脚本：

   ```bash
   server/deploy/migrate.sh root@旧服务器IP root@新服务器IP 新服务器IP
   ```

脚本会自动完成以下几步：

1. 旧服务器停服并打包
2. 传到新服务器
3. 用同一个根证书给新 IP 签发证书
4. 启动服务并检查是否正常

完成后，在两台手机的 App「设置 → 服务器地址」里改成新地址。**App 不需要重新安装**。

旧服务器只停服、不删数据。确认新服务器一切正常后，再自己清理旧服务器。
